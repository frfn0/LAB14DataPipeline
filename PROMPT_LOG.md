## Задание 1. Разработка сборщика данных на Go

### Промпт

> давай задание 14
>
> продолжай задание 10

### Результат

Написан сборщик на Go, который обходит два эндпоинта OpenWeatherMap —
текущую погоду и прогноз на пять дней с шагом три часа — и пишет результат
в JSON-файл, по одному объекту на строку.

Каждый город обрабатывается отдельной горутиной, записи передаются в канал,
письмо идёт отдельной горутиной. Число городов одновременно ограничивается
параллелизмом. Ошибка одного города не останавливает сбор остальных.

Ответы двух эндпоинтов приводятся к одному типу `WeatherRecord`, время
наблюдения переводится в часовой пояс города. Ключ API читается из
переменной окружения и не пишется в лог.

Собрано 410 записей по десяти городам России за 3.08 с. Замер: при
последовательном сборе те же данные собираются 15.09 с, выигрыш параллельной
сборки — 4.9 раза.

Написано 21 тест: разбор обоих эндпоинтов, перевод времени, ошибки
источника, пустой и битый ответ, отмена по контексту, разбор флагов,
маскирование ключа.

### Решения, принятые при проектировании

- Время наблюдения переводится в часовой пояс города, а не остаётся в UTC.
  Разница между Якутском и Москвой девять часов: без перевода все города в
  отчёте выглядели бы как одно и то же время суток, и сравнивать их было бы
  бессмысленно.
- Ответы двух эндпоинтов приводятся к одному типу. Структуры у них разные,
  а конвейер на Python должен получить однородную таблицу.
- Параллелизм ограничен параметром, а не равен числу городов. Без
  ограничения десять городов создали бы десять одновременных соединений с
  источником.
- Ошибка одного города не прерывает сбор остальных: одна опечатка в названии
  обнуляла бы весь прогон.
- Время HTTP-запроса сохраняется в данных. Оно пригодится в задании 8 при
  сравнении быстродействия этапов конвейера.
- Ключ API не пишется в лог, только маска. При этом маска одинакова для всех
  запусков, так что отличить ключ от другой строки в логе можно.
- Постоянные соединения в транспорте выключены: на этой машине на
  переиспользуемом соединении тело большого ответа не приходило вовсе.

### Неудачные попытки и исправления

| Что пошло не так | Почему | Как исправлено |
|------------------|--------|----------------|
| Первый запуск собрал ноль записей за 41 с: все запросы к прогнозу истекли по таймауту | Причина сначала неочевидна. curl отвечал за 1.1 с и отдавал полный ответ, значит источник был жив | Проверка на четырёх вариантах транспорта (IPv4, HTTP/1.1, HTTP/2, tcp4) показала, что все варианты работают, и дело не в протоколе |
| Часть тестов проверки транспорта показала код 404 | В пробной программе адрес склеивался двумя знаками вопроса: `?q=Moscow?units=metric`, и город не находился | URL собирается через правильные разделители, проверка повторена |
| Проверка на повторно используемом соединении показала, что заголовки приходят с кодом 200, а тело — ноль байт ровно за 20 с | Тело большого ответа (17 КБ) не приходит вовсе, тогда как текущая погода (488 байт) по тому же соединению проходит | В транспорте включён `DisableKeepAlives`: каждый запрос идёт по своему соединению, все ответы приходят целиком за 0.85 с |
| Записи текущей погоды терялись при сбое прогноза по тому же городу | `CollectOne` возвращает ошибку целиком, и уже собранное наблюдение не доходило до записи | При сбое эндпоинта прогноза собранное наблюдение сохраняется, город помечается ошибкой в лог |
| Ожидание в тесте времени наблюдения было неверным | Unix-время 1791406800 — это 21:00 UTC, то есть уже следующие сутки по Москве | Ожидание исправлено на `2026-10-08T00:00:00+03:00` — именно этот случай и показывает, зачем нужен перевод в часовой пояс города |
| go.mod не читался: `unexpected input character '\ufeff'` | Файл создан через PowerShell, который добавил метку порядка байтов | Метка удалена, файл записан без неё |
| Тесты маскирования ключа не совпали с кодом | Ожидания в тесте были записаны не по той логике: короткие ключи скрываются целиком, у длинных показываются четыре первых и четыре последних символа | Ожидания приведены к поведению кода |
| `&httpClient(cfg.Timeout)` не компилируется | В Go нельзя взять адрес результата вызова функции, а функция уже возвращает указатель | Указатель убран: передаётся сам результат |
| Тест «время запроса не измерено» падал примерно в одном прогоне из двенадцати | Проверялось `elapsed > 0`, но тестовый сервер отвечает за микросекунды, и на Windows длительность такого запроса округляется до нуля | Проверяется, что измеренное время попало в поле `request_ms` записи, а не что оно положительно |
| Пакет тестов на клиент шёл 2.6 с вместо 0.7 с | В тесте отмены запроса обработчик спал 2 с и продолжал работать после падения теста, из-за чего закрытие тестового сервера зависало | Обработчик ждёт отмены запроса вместо фиксированной паузы |

### Проверка

- Время наблюдения приведено к часовому поясу города, время сбора остаётся в
  UTC
- Ключ API в логе не появляется, только маска `50b2...8eaa`
- `go build ./...`, `go vet ./...`, `gofmt -l .` — чисто
- `go test ./...` — 21 тест, оба пакета ok
