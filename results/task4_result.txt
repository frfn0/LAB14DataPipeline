Задание 4. Импорт данных в Python (Polars): фактический вывод
===========================================================

Дата проверки: 2026-10-07
Инструменты: Python 3.10.6, Polars 2.0.0, pytest 9.0.3, ruff

Требование методички
--------------------

"Написать Python-скрипт, который загружает собранные JSON-файлы в DataFrame
(Polars). Вывести первые 5 строк и базовую информацию о данных (типы,
количество строк, пропуски)."

Что сделано
-----------

1. Общий модуль конвейера, pipeline/common.py.

   Пути, схема данных и вспомогательные функции вынесены отдельно: их
   читают все следующие шаги конвейера, а не только импорт.

2. Загрузка данных, pipeline/import_data.py.

   Скрипт читает все файлы `data/raw/*.jsonl` и объединяет их в одну
   таблицу. Показывает первые пять строк, типы полей, количество строк и
   пропуски, а также общие сведения: число файлов, городов, эндпоинтов,
   размер в памяти и период наблюдений.

3. Схема данных задана явно.

   Поля и их типы перечислены в `WEATHER_SCHEMA` и передаются в
   `read_ndjson`. Причины:

   - вывод типов по первым строкам файла превращает целочисленный счётчик в
     дробный, если встретится одно пустое значение;
   - изменение контракта сборщиком приводит к ошибке импорта, а не к тихой
     смене типа посреди конвейера;
   - состав полей виден в одном месте рядом с описанием их смысла.

4. Проверка контракта.

   Polars при чтении с готовой схемой не требует наличия всех полей:
   отсутствующее поле просто становится пустым. Изменение контракта сборщиком
   прошло бы молча, а данные появились бы в отчёте как пропуски. Поэтому перед
   чтением состав полей первой записи сравнивается со схемой, и расхождение
   приводит к ошибке с перечислением недостающих и лишних полей.

5. Тесты: 16 тестов на pytest.

   Проверяются схема (совпадение с контрактом, целые счётчики, дробные
   температуры), загрузка (собранный файл читается без потерь, типы
   совпадают со схемой, несколько файлов объединяются, порядок файлов
   сохраняется, пустой файл и расхождение контракта приводят к ошибке) и
   вспомогательные функции.

Читаемость вывода
-----------------

Первые пять строк выводятся обычным текстом, полями по строкам и записями по
колонкам. Встроенный вывод Polars усекает таблицу: при двадцати семи полях по
пять записей она шире экрана, и середина обрезалась — часть данных просто не
попадала в отчёт. Повёрнутый вариант обрезался по высоте. Текстовая таблица
показывает все поля и все пять записей.

Найденные при проверке дефекты
------------------------------

1. Файл скрипта был назван `04_import.py`. Такое имя не запускается командой
   `python -m`: имя модуля должно быть идентификатором. Файл переименован в
   `import_data.py`, номер задания остался в заголовке и в README.

2. `counts.sum()` у таблицы в одну строку возвращает таблицу, а не число:
   `int(counts.sum())` падал с TypeError. Итог считается по горизонтали:
   `counts.sum_horizontal().item()`.

3. У таблицы `null_count()` нет метода `items`. Имена полей и их значения
   берутся раздельно: `zip(counts.columns, counts.row(0))`.

4. Тест на отсутствующее поле контракта не сработал: Polars при чтении с
   готовой схемой молча заполняет отсутствующее поле пустыми значениями. Это
   была настоящая дыра - расхождение контракта прошло бы незаметно. Добавлена
   проверка состава полей перед чтением, и тест теперь проверяет три случая:
   нет поля, лишнее поле, пустой файл.

5. Первая таблица первых строк обрезалась по ширине, повёрнутая - по высоте.
   Обе попытки показаны в выводе выше: они и натолкнули на текстовый вариант.
